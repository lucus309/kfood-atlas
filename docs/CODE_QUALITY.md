# 코드 품질 점검과 리팩터링

## 범위와 기준

2026-11-04의 웹 UI·분석 모듈·AI 서버·빌드/개발 스크립트·테스트를 점검했다. 목표는 기능·추천 기준·원자료를 바꾸지 않고, 수정 위치를 찾기 쉽고 같은 로직을 여러 곳에서 고치지 않아도 되는 구조를 만드는 것이다.

- [Martin Fowler, Refactoring](https://refactoring.com/): 관찰 가능한 동작을 보존하며 작은 변경으로 개선한다.
- [Google, What to look for in a code review](https://google.github.io/eng-practices/review/reviewer/looking-for.html): 역할·기능·복잡도·테스트·명명·주석을 검토한다. 미래 요구를 추측한 과도한 일반화는 피한다.
- [Martin Fowler, Yagni](https://martinfowler.com/bliki/Yagni.html): 현재 필요가 확인된 기능과 추상화만 만든다.

같이 생긴 코드를 무조건 합치지 않는다. 시장 기본점수와 관측 추천 지수의 백분위·동률 규칙은 서로 다르므로 별도 계산을 보존한다. 숫자 표시도 성장률·점유율·점유율 변화의 단위와 정밀도를 구분한다.

## 점검 결과와 적용

| 발견한 문제 | 변경 | 확인 방법 |
|---|---|---|
| 화면 진입점에 SVG·아이콘·숫자 표시·데이터 로딩 집중 | `charts`, `ui-icons`, `ui-format`, `data-loader` 분리 | 국가 상세·그래프·필터·모바일 화면 확인 |
| 화면과 AI 도구에 분석 파이프라인과 국가명 처리 중복 | `market-analysis`, `countries`를 양쪽에서 사용 | 100개 제품/기간 조합의 기존 결과 대조 |
| 선택 목록을 순위 계산 중 반복 정렬 | 정렬 결과와 시나리오별 점수 목록을 한 번 생성 | 동일 순위·동점·CSV 검증 |
| 필터 변경 없이 화면 렌더링마다 TOP3 재선정 | 제품/시작/종료 기준의 마지막 분석 결과 재사용 | 검색/후보 선택으로 비교집단이 바뀌지 않는지 검사 |
| 추천 규칙과 해석/자료 품질 처리가 한 파일에 혼재 | `recommendation-policy`, `recommendation-evidence`, `recommendations` 구분 | 독립 기준 결과와 9개 시나리오 테스트 |
| 여러 CSV 생성기의 BOM·이스케이프·줄바꿈 중복 | `csv` 공통 모듈과 기존 export 호환 유지 | CSV 내용까지 기존 스냅샷과 비교 |
| 채팅 Worker가 입력·인증·DB·제한·스트림을 모두 처리 | `api-key`, `chat-request`, `chat-storage`, `chat-stream`, `chat-tools` 분리 | 잘못된 입력·캐시/한도·도구 왕복·API 실패 검사 |
| 채팅 UI에 네트워크 스트림 파싱이 섞임 | `chat-transport` 분리 | 한글 UTF-8 분할·마지막 줄·오류 응답 검사 |
| 제한 숫자와 환경변수 처리 반복 | `chat-config`, `scripts/env`, SQLite 어댑터 재사용 | 현재 한도 유지·API 키 없는 로컬 실행 확인 |
| 원본 JS/CSS가 압축된 긴 줄로 저장 | Prettier 설정과 포맷 확인 명령 추가 | `npm run format:check` |

필수 데이터 파일은 병렬로 읽고, 선택적인 AI 설명 파일의 실패는 기존처럼 대시보드 분석을 중단시키지 않는다. 숫자 표시용 Intl 포맷터도 셀마다 다시 만들지 않고 재사용한다.

## 검증

리팩터링 전에 저장한 운영 소스의 10개 제품 × 모든 유효한 10개 비교 기간, 총 100개 조합을 기준으로 했다. 각 조합의 모든 분석 행, 추천/동점 목록, 추천 설명, CSV를 정규화한 뒤 해시로 비교한다. 195개 탐색 행을 포함해 총 19,500개 행의 결과가 대상이다. `fixtures/refactor-baseline.json`이 변경 전 기준이며, `test-analysis-regression.mjs`는 이를 현재 공통 분석 모듈과 비교한다.

추가 `test-chat-runtime.mjs`는 유료 API 호출 없이 모델 응답을 대체해 도구 선택→조회 결과 반환→최종 답변, 중복 출처 정리, API 오류, 4회 호출 한도, 캐시·요청 제한, 분할 스트림 수신을 검증한다.

일반 요청의 출력과 순위는 보존한다. 별도로 발견한 두 경계 오류는 수정했다: JSON null/메시지 null 입력을 서버 오류 대신 400으로 거부하고, 마지막 줄바꿈 없는 스트림의 최종 이벤트를 놓치지 않는다.

## 구조와 유지 원칙

프런트엔드 원본은 계속 `dist/`에 둔다. 기존 빌드·정적 자산 제공 구조를 바꾸는 프레임워크 전환은 하지 않았다. `app.mjs`는 화면 조립과 이벤트 연결을 담당하고, DOM 없는 계산/그래프 함수는 독립 모듈에 둔다. `server/worker.mjs`는 요청을 해당 처리기로 전달한다.

CSS의 기존 반응형 규칙과 덮어쓰기 순서는 화면 보존을 위해 유지하고 서식만 정리했다. 장문의 화면 마크업을 모두 범용 컴포넌트로 바꾸거나 과거 수집 파이프라인까지 재작성하지 않았다. 이 변경이 모든 설계 문제를 없앴다거나 추천 예측력을 개선했다고 주장하지 않는다.
